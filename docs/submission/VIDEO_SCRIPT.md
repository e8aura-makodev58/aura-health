## Agentic demonstration question

“Did activity drop before or after sleep timing changed, and how do the last
two weeks compare with the two before?”

Use this as an actual question, not a hard-coded scripted answer. Inspect the
model's chosen signal keys, exact periods and successful tool calls. Then show
the checked answer with citations and any removed claims. Do not state that
independent verification establishes clinical truth.

If the model falls back, explain briefly: “The proposed wording did not pass
the checks, so AURA shows related recorded facts. The investigation remains
inspectable.” Do not portray those facts as a completed answer. A separately
recorded successful investigation may illustrate the capability if clearly
identified, but must not replace the failure in a reliability claim.

## Build reflection — factual talking points

- We separated safety policy, longitudinal reasoning and language generation.
- We gave the agent read-only, patient-scoped tools rather than database authority.
- Versioned skills/prompts and exact source checks made failures diagnosable.
- CodeBuddy helped with the UI redesign; Miora supplied artwork. Use only genuine
  sessions/assets verified in the supplied evidence. Do not claim WorkBuddy usage
  or tasks that cannot be traced.
- Useful tool tip: write boundaries/acceptance checks before requesting a redesign,
  and preserve the APIs and safety paths while improving presentation.

## Recording acceptance

Confirm runtime 5–8 minutes, readable UI/diagram, clear narration, real Q&A steps,
source/fallback honesty, reflection/tool tips, no secrets/real patient data,
viewer-accessible link and consistency with the submitted code. Captions and
chapter markers are recommended, not invented organizer requirements.
Marketing Intro/Midpoint/Closing clips alone do not meet the walkthrough requirement.
